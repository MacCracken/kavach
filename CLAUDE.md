# Kavach — Claude Code Instructions

## Project Identity

**Kavach** (Hindi: armor/shield) — Sandbox execution framework — 10 backends, strength scoring (0-100), policy engine, 3-scanner pipeline, credential proxy (direct + HTTP), runtime guards, threat classification, audit chain

- **Type**: Cyrius binary **and** source-level library. The `[lib]` profile was earned at v3.6.0 (first consumer: mehman's M1 host) — kavach ships a committed `dist/kavach.cyr` bundle, plus the lean `dist/kavach-confine.cyr` from `[lib.confine]` (v3.12.3, for thoth), both generated by `cyrius distlib --all` (the standard first-party dist flow, same as sigil/patra/bhumi; CI gates their freshness — plain `cyrius distlib` folds only `[lib]`); consume it via `[deps.kavach] modules = ["dist/kavach.cyr"]`. See [ADR-006](docs/adr/006-library-surface-and-bundle-generation.md). `src/main.cyr` remains the in-tree smoke/demo program entry.
- **License**: GPL-3.0-only
- **Language**: Cyrius (pinned at `6.6.6` in `cyrius.cyml`; sigil 3.12.18 — see hazard (4); agnosys was dropped at v3.5.0, its security backends internalized as `src/` modules — the `agnosys → agnodrm` decomposition). Four live pin-move hazards: (1) **opt-in stdlib modules** — since sigil 3.6, `ct`/`keccak`/`thread`/`thread_local` are not in the cyrius auto-prepend union and must be in `[deps]` + reachable, or a crypto path SIGILLs (exit 132) on a `ud2` trap at runtime (see CHANGELOG 3.4.1/3.4.2); (2) **the 6.2 stdlib consolidation** — the standalone `json`/`base64` modules were folded into `bayan` and `bigint` was retired (sigil bundles its own `u256`/`u384`), so a 6.1→6.2 move must re-point `[deps]` (`json` → `bayan`, drop `bigint`) or `cyrius deps` fails to resolve (see CHANGELOG 3.4.2); (3) **symbol collisions with sigil** — cyrius auto-prepends every `[deps.*]` module into the compilation unit, so a name kavach and sigil both define resolves silently by source order under last-def-wins. sigil 3.12.8 namespaced its error constructors `err_*` → `sigil_err_*` and kavach namespaced its own `err_*` → `kavach_err_*` at 3.11.13; grep a pin/dep move for new `duplicate fn` warnings rather than ignoring them (see CHANGELOG 3.11.13); (4) **the toolchain snapshot's sigil wins over `[deps.sigil]`** — kavach declares `tls`, the stdlib's `tls_native.cyr` includes `lib/sigil.cyr`, so `cyrius deps` copies sigil from the pinned toolchain's snapshot, and since cc 6.5.39 it refuses to let the `[deps.sigil]` artifact overwrite a stdlib leaf it already copied (`warning: refusing to overwrite stdlib leaf 'sigil'`). The `tag` is therefore inert: keep it equal to the snapshot's sigil (`grep -m1 Version ~/.cyrius/versions/<pin>/lib/sigil.cyr`) so the manifest names what the build uses, and take a newer sigil by moving the cyrius pin, not the tag (CHANGELOG 3.12.6). Two former hazards were fixed upstream in cc 6.5.28, both filed from kavach 3.11.14: a declared stdlib module first reached transitively losing its `include` (the explicit `include "lib/chrono.cyr"` in `src/util.cyr`, `tests/kavach.fcyr` and `tests/samay_integration.tcyr` is now harmless redundancy), and the 4095-byte `_auto_deps` manifest window (now 65535, failing loud). Validate a pin move with a clean `deps → build → lint → vet → test → bench` run; diff the `duplicate fn` name set against the previous build, and treat a new `undefined function` on a stdlib symbol as a module missing from `[deps]` (or from a dep's `.deps` sidecar).
- **Version**: SemVer, v3.12.6 (Cyrius port; Rust v1.x/v2.x archived in git history pre-3.1.1)
- **Genesis repo**: [agnosticos](https://github.com/MacCracken/agnosticos)
- **Philosophy**: [AGNOS Philosophy & Intention](https://github.com/MacCracken/agnosticos/blob/main/docs/philosophy.md)
- **Standards**: [First-Party Standards](https://github.com/MacCracken/agnosticos/blob/main/docs/development/applications/first-party-standards.md)
- **Recipes**: [zugot](https://github.com/MacCracken/zugot) — takumi build recipes

## Development Process

### P(-1): Scaffold Hardening (before any new features)

0. Read roadmap, CHANGELOG, and open issues — know what was intended before auditing what was built
1. Test + benchmark sweep of existing code
2. Cleanliness check: `cyrius fmt` (no drift), `cyrius lint` (0 warnings), `cyrius vet src/main.cyr` (include-graph audit), `cyrius audit` (full chain — fmt/lint/vet/deny/test/bench/doc)
3. Get baseline benchmarks (`./scripts/bench-history.sh`)
4. Initial refactor + audit (performance, memory, security, edge cases)
5. Cleanliness check — must be clean after audit
6. Additional tests/benchmarks from observations
7. Post-audit benchmarks — prove the wins
8. Repeat audit if heavy
9. Documentation audit — ADRs, source citations, guides, examples (see Documentation Standards in first-party-standards.md)

### Development Loop (continuous)

1. Work phase — new features, roadmap items, bug fixes
2. Cleanliness check: `cyrius fmt` (no drift), `cyrius lint` (0 warnings), `cyrius vet src/main.cyr` (include-graph audit), `cyrius audit` (full chain — fmt/lint/vet/deny/test/bench/doc)
3. Test + benchmark additions for new code
4. Run benchmarks (`./scripts/bench-history.sh`)
5. Audit phase — review performance, memory, security, throughput, correctness
6. Cleanliness check — must be clean after audit
7. Deeper tests/benchmarks from audit observations
8. Run benchmarks again — prove the wins
9. If audit heavy → return to step 5
10. Documentation — update CHANGELOG, roadmap, docs, ADRs for design decisions, source citations for algorithms/formulas, update docs/sources.md, guides and examples for new API surface, verify recipe version in zugot; refresh `docs/doc-health.md` row for any doc you touched
11. Version check — `VERSION`, `cyrius.cyml` (which pulls VERSION via `${file:VERSION}`), recipe (in zugot) all in sync
12. **Release benchmark — on every version release, run `./scripts/bench-history.sh <version>` (label = the new SemVer, e.g. `3.3.0`) so `benches/bench-history.csv` carries a per-release row. Compare against the prior release's row, call out deltas/regressions in the CHANGELOG, and never cut a release without this baseline recorded.**
13. Return to step 1

### Key Principles

- **Never skip benchmarks.** Numbers don't lie. The CSV history (`scripts/bench-history.sh`) is the proof.
- **Benchmark every release.** Every version release records a `bench-history.csv` row labeled with its SemVer (`./scripts/bench-history.sh <version>`). The per-release history is how deltas and regressions are tracked across versions — a release without a recorded benchmark row is not done.
- **Tests + benchmarks are the way.** Minimum 80%+ coverage target.
- **Own the stack.** If a first-party Cyrius crate wraps an external surface, depend on the first-party crate (sigil for crypto, sandhi for HTTP, patra for SQL, sakshi for tracing, agnosys for syscall glue).
- **No magic.** Every operation is measurable, auditable, traceable.
- **Borrow when you can, allocate only when you must.** Cyrius `Str` borrows over `cstring` copies; reuse buffers across calls in the hot path.
- **Vec arena over HashMap** — when indices are known, direct access beats hashing.
- **`include` over re-implementing** — the cyrius stdlib + the first-party tree carry shared primitives; consumers pull only what their entry points actually transitively reach.
- **Structured logging on every external operation** — backend exec, scanner verdict, audit-chain append, quarantine write all emit a trace line so the audit trail is reconstructable.
- **`# SAFETY:`** comment on every raw-syscall or pointer-arithmetic block — the line above must state the invariant the call relies on.
- **async-signal-safe only in pre_exec** — no heap allocation, no mutex, no tracing after fork.

## DO NOT
- **Do not commit or push** — the user handles all git operations (commit, push, tag)
- **NEVER use `gh` CLI** — use `curl` to GitHub API only
- **Do not bump the Cyrius pin** without a clean `deps → build → lint → vet → test → bench` run on the new toolchain across the first-party tree. The pin is `6.6.6`. A pin move can require migrating renamed/retired stdlib + sigil symbols (e.g. sigil's `ct_eq` → stdlib `ct_eq_bytes_lens` in the 3.x line — CHANGELOG 3.3.0; the 6.6.0 `Result` value form — CHANGELOG 3.12.4), **declaring newly opt-in stdlib modules** in `[deps]` (e.g. `thread_local`, `async` — CHANGELOG 3.4.1), **re-pointing consolidated stdlib modules** (`json`/`base64` → `bayan`, drop retired `bigint` — CHANGELOG 3.4.2), **re-namespacing symbols a dep has just claimed** (sigil 3.12.8's `err_*` → `sigil_err_*` — CHANGELOG 3.11.13), and **re-pinning `[deps.sigil]` to the new snapshot's sigil** (CHANGELOG 3.12.6); a missing opt-in module builds clean but SIGILLs at runtime, a retired module name makes `cyrius deps` fail outright, a collided name compiles to a `duplicate fn` warning that resolves by source order instead of erroring, and a sigil tag that differs from the snapshot's is silently ignored.
- **Do not run `cyrius fmt` against a non-pinned local toolchain** — fmt output is minor-version-sensitive; running a non-`6.6.6` fmt and committing creates new drift against CI's `6.6.6`. (The pin currently matches the installed `cycc`; if `cycc` later drifts ahead of the pin, skip fmt writes until the pin catches up.) `cyrius fmt <file>` rewrites in place; use `--check` to only report.
- **Do not write commentary into `cyrius.cyml`** — it is configuration, not a ledger or a changelog. Release history goes in CHANGELOG, design rationale in an ADR or `docs/`, and pin-move hazards and procedure here. (Trimmed from 12.8 KB to 3.1 KB at v3.12.6.)
- **Do not regenerate `dist/` with plain `cyrius distlib`** — it folds only `[lib]` and leaves `dist/kavach-confine.cyr` stale; use `cyrius distlib --all`.
- **Do not hardcode an x86_64 syscall number or open-flag value** — use the stdlib's names (`sys_*`, `SYS_*`, `O_*`). aarch64 runs x86 `91` as `capset` and reads x86 `O_NOFOLLOW` as `O_LARGEFILE`, silently (CHANGELOG 3.12.6). After touching a syscall site, build with `cyrius build --aarch64`, which warns on a raw number it can name, and check behaviour under `qemu-aarch64 -strace`. Open files through `file_open`, never raw `sys_open`: on agnos `sys_open` is `(name, namelen, AO_flags)`, and `file_open` maps the `O_*` names (which `lib/io.cyr` defines there) to `AO_*`.
- Do not commit `lib/` — it's gitignored; `cyrius deps` is the source of truth
- Do not commit `build/` — gitignored
- Do not add unnecessary dependencies — keep it lean
- Do not skip benchmarks before claiming performance improvements
